## Sprint 1

### US-01: สร้างประกาศสิ่งของให้ยืม

- **As a:** นักศึกษาและบุคลากรของมหาวิทยาลัยธรรมศาสตร์ที่มี TU Account
- **I want to:** สร้างประกาศสิ่งของที่ตนเองต้องการเปิดให้ผู้อื่นยืม
- **So that:** นำสิ่งของที่ไม่ได้ใช้งานมาแบ่งปันแก่เพื่อนร่วมมหาวิทยาลัย
- **Priority:** High
- **Estimate:** 3 points

#### Pre-conditions

1. ผู้ใช้อยู่ในสถานะเข้าสู่ระบบ
2. ผู้ใช้อยู่ที่หน้าฟอร์มสร้างประกาศสิ่งของ

#### Post-conditions

1. ข้อมูลประกาศถูกบันทึกลงระบบด้วยสถานะ `Available`
2. ประกาศใหม่ปรากฏในรายการสิ่งของและผู้ใช้งานทุกคนสามารถมองเห็นได้

#### Acceptance Criteria & Test Cases

- [ ] **Test Case 1:** กรอกข้อมูลครบถ้วนถูกต้อง (ชื่อ, หมวดหมู่, รูปภาพ, รายละเอียด) ระบบบันทึกสำเร็จและแสดงประกาศในรายการของทั้งหมด
- [ ] **Test Case 2:** ส่งฟอร์มโดยเว้นว่างช่องข้อมูลบังคับ ระบบปฏิเสธการสร้างและแจ้งเตือนให้กรอกข้อมูลให้ครบถ้วน
- [ ] **Test Case 3:** อัปโหลดไฟล์รูปภาพที่ไม่ใช่รูปแบบที่กำหนดหรือไม่ถูกต้อง ระบบแจ้งเตือนและไม่สร้างประกาศ

---

### US-02: แสดงรายการสิ่งของที่เปิดให้ยืม

- **As a:** นักศึกษาและบุคลากรของมหาวิทยาลัยธรรมศาสตร์ที่มี TU Account
- **I want to:** ดูรายการสิ่งของทั้งหมดที่มีสถานะพร้อมให้ยืมบนบริการ
- **So that:** ทราบว่ามีสิ่งของใดบ้างที่สามารถขอยืมได้ในระบบ
- **Priority:** Medium
- **Estimate:** 2 points

#### Pre-conditions

1. User อยู่ในสถานะเข้าสู่ระบบและอยู่ในหน้าหลักหรือหน้ารายการของให้ยืม
2. เซิร์ฟเวอร์และฐานข้อมูลทำงานและเชื่อมต่อได้ตามปกติ

#### Post-conditions

1. หน้าจอแสดงรายการสิ่งของทั้งหมดที่มีสถานะ `Available`
2. สิ่งของที่ถูกลบหรือถูกยืมไปแล้วต้องไม่ถูกนำมาแสดงในรายการพร้อมให้ยืม

#### Acceptance Criteria & Test Cases

- [ ] **Test Case 1:** มีประกาศสิ่งของที่พร้อมให้ยืมอยู่ใน Database ระบบต้องดึงรายการมาแสดงผลอย่างถูกต้อง ครบถ้วน
- [ ] **Test Case 2:** ไม่มีสิ่งของที่พร้อมให้ยืมใน Database ระบบต้องแสดงข้อความแจ้งเตือนสถานะ ไม่มีรายการของ และหน้าจอต้องไม่เกิดข้อผิดพลาด
- [ ] **Test Case 3:** สิ่งของถูกเปลี่ยนสถานะเป็นถูกยืมหรือถูกลบออก เมื่อโหลดรายการใหม่ สิ่งของนั้นต้องไม่ปรากฏในหน้าแสดงผล

---

### US-03: ส่งคำขอยืมสิ่งของ

- **As a:** นักศึกษาและบุคลากรของมหาวิทยาลัยธรรมศาสตร์ที่มี TU Account
- **I want to:** ส่งคำขอยืมสิ่งของ พร้อมระบุช่วงวันเวลาและเหตุผลในการขอยืม
- **So that:** แจ้งความประสงค์ไปยังผู้ให้ยืมเพื่อขอทำข้อตกลงการใช้งานสิ่งของ
- **Priority:** Low
- **Estimate:** 1 point

#### Pre-conditions

1. User ที่กำลังดำเนินการอยู่ในสถานะเข้าสู่ระบบ
2. สิ่งของเป้าหมายมีสถานะ `Available` และผู้ขอยืมไม่ใช่เจ้าของสิ่งของนั้น
3. ผู้ขอยืมอยู่ในหน้ารายละเอียดของสิ่งของชิ้นดังกล่าว

#### Post-conditions

1. ข้อมูลคำขอยืมถูกบันทึกเข้าสู่ Database ด้วยสถานะ `Pending`

#### Acceptance Criteria & Test Cases

- [ ] **Test Case 1:** ผู้ขอยืมกรอกข้อมูลและกดส่งคำขอยืมอย่างถูกต้อง ระบบสร้างรายการคำขอใน Database สถานะเป็น `Pending`
- [ ] **Test Case 2:** ผู้ขอยืมพยายามกดยืมสิ่งของของตัวเอง ระบบปฏิเสธการทำรายการและไม่สร้างคำขอใน Database
- [ ] **Test Case 3:** ผู้ขอยืมพยายามกดยืมสิ่งของที่มีสถานะไม่พร้อมใช้งาน ระบบแจ้งเตือนและไม่อนุญาตให้ส่งคำขอ

### US-04: แก้ไขและลบประกาศสิ่งของให้ยืม

- **As a:** นักศึกษาและบุคลากรของมหาวิทยาลัยธรรมศาสตร์ที่มี TU Account ที่เป็นเจ้าของประกาศ
- **I want to:** แก้ไขรายละเอียดหรือลบประกาศสิ่งของที่ตนเองเคยสร้างไว้
- **So that:** ข้อมูลสิ่งของเป็นปัจจุบันหรือยกเลิกการเปิดให้ยืมเมื่อไม่สะดวก
- **Priority:** Low
- **Estimate:** 1 point

#### Pre-conditions

1. ผู้ใช้อยู่ในสถานะเข้าสู่ระบบ
2. ผู้ใช้ต้องเป็นเจ้าของประกาศนั้น
3. ประกาศหรือสิ่งของชิ้นนั้นต้องอยู่ในสถานะ `Available` เท่านั้น

#### Post-conditions

1. (กรณีแก้ไข) รายละเอียดประกาศถูกอัปเดตเป็นข้อมูลใหม่ทันที
2. (กรณีลบ) ประกาศถูกลบ เปลี่ยนสถานะเป็น `Deleted` และไม่แสดงผลในระบบ

#### Acceptance Criteria & Test Cases

- [ ] **Test Case 1:** เจ้าของแก้ไขรายละเอียดสิ่งของ ระบบอัปเดตและแสดงข้อมูลใหม่ในหน้าประกาศทันที
- [ ] **Test Case 2:** เจ้าของกดลบประกาศที่สถานะ `Available` ประกาศถูกลบและไม่แสดงผลในระบบ
- [ ] **Test Case 3:** พยายามแก้ไขหรือลบประกาศในขณะที่สิ่งของมีสถานะ `Borrowed` ระบบต้องปฏิเสธคำขอและแจ้งเตือนผู้ใช้งาน
- [ ] **Test Case 4:** ผู้ใช้คนอื่นที่ไม่ได้เป็นเจ้าของ พยายามเข้าถึงปุ่มแก้ไขหรือลบผ่านทาง URL ระบบต้องปฏิเสธสิทธิ์

### US-05: การตอบรับหรือปฏิเสธคำขอยืมสิ่งของ

- **As a:** นักศึกษาและบุคลากรของมหาวิทยาลัยธรรมศาสตร์ที่มี TU Account ที่เป็นเจ้าของสิ่งของ
- **I want to:** กดยอมรับหรือปฏิเสธคำขอยืมสิ่งของของตนเอง
- **So that:** ตัดสินใจเลือกให้ยืมหรือไม่ให้ยืมได้อย่างเป็นทางการในระบบ
- **Priority:** Low
- **Estimate:** 1 point

#### Pre-conditions

1. User ที่กำลังดำเนินการอยู่ในสถานะเข้าสู่ระบบ
2. User เป็นเจ้าของสิ่งของในคำขอนั้น
3. มีคำขอยืมค้างอยู่ในระบบสำหรับสิ่งของชิ้นนั้นด้วยสถานะ `Pending`

#### Post-conditions

1. (กรณีผู้ให้ยืมยอมรับ) สถานะของคำขอเปลี่ยนเป็น `Accepted` และสถานะสิ่งของเปลี่ยนเป็น `Reserved` เพื่อรอขั้นตอนส่งมอบ
2. (กรณีผู้ให้ยืมปฏิเสธ) สถานะคำขอเปลี่ยนเป็น `Rejected` และยังคงสถานะสิ่งของเป็น `Available` สำหรับผู้ยืมอื่น

#### Acceptance Criteria & Test Cases

- [ ] **Test Case 1:** ผู้ให้ยืมกดยอมรับคำขอ สถานะคำขอเปลี่ยนเป็น `Accepted` และสถานะสิ่งของเปลี่ยนเป็น `Reserved`
- [ ] **Test Case 2:** ผู้ให้ยืมกดปฏิเสธคำขอ สถานะคำขอเปลี่ยนเป็น `Rejected` และสถานะสิ่งของยังคงเป็น `Available`
- [ ] **Test Case 3:** ผู้ใช้ที่ไม่ได้เป็นเจ้าของสิ่งของ พยายามกดยอมรับหรือปฏิเสธคำขอ ระบบต้องปฏิเสธการทำรายการ
