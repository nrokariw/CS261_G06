## Sprint 2

### US-06: บันทึกหลักฐานการส่งมอบสิ่งของ

- **As a:** นักศึกษาและบุคลากรของมหาวิทยาลัยธรรมศาสตร์ที่มี TU Account
- **I want to:** บันทึกและอัปโหลดหลักฐานสภาพสิ่งของในขั้นตอนการส่งมอบ/รับของ
- **So that:** มีหลักฐานยืนยันสภาพเริ่มต้นและวันที่รับมอบสิ่งของ ป้องกันข้อพิพาทเรื่องของชำรุดมาก่อนหน้า
- **Priority:** High
- **Estimate:** 3 points

#### Pre-conditions

1. User อยู่ในสถานะเข้าสู่ระบบ
2. User เป็นคู่กรณีในรายการยืมนั้น
3. รายการยืมอยู่ในสถานะ `Accepted`

#### Post-conditions

1. ข้อมูลรูปภาพ สภาพสิ่งของ และ Timestamp ถูกผูกเข้ากับ Transaction ใน Database
2. สถานะของรายการยืมอัปเดตเป็น `Borrowed`

#### Acceptance Criteria & Test Cases

- [ ] **Test Case 1:** User บันทึกหลักฐานการส่งมอบ/รับของถูกต้อง ข้อมูลและรูปภาพถูกบันทึกลง Database สถานะของรายการยืมอัปเดตเป็น `Borrowed`
- [ ] **Test Case 2:** User ส่งแบบฟอร์มบันทึกหลักฐานการส่งมอบโดยไม่แนบรูปภาพ หรือกรอกข้อมูลบังคับไม่ครบ ระบบต้องแจ้งเตือนข้อผิดพลาดและไม่บันทึกข้อมูลลง Database
- [ ] **Test Case 3:** ผู้ใช้ที่ไม่ได้เป็นคู่กรณี พยายามส่งข้อมูลบันทึกหลักฐานการส่งมอบ ระบบต้องปฏิเสธการดำเนินการ

### US-07: บันทึกหลักฐานการส่งคืนสิ่งของ

- **As a:** นักศึกษาและบุคลากรของมหาวิทยาลัยธรรมศาสตร์ที่มี TU Account
- **I want to:** บันทึกและอัปโหลดหลักฐานสภาพสิ่งของในขั้นตอนการส่งคืน
- **So that:** มีหลักฐานยืนยันว่าได้ส่งมอบของคืนตามสภาพจริง ป้องกันข้อพิพาทเรื่องความเสียหายหลังการใช้งาน
- **Priority:** High
- **Estimate:** 3 points

#### Pre-conditions

1. User อยู่ในสถานะเข้าสู่ระบบ
2. User เป็นคู่กรณีในรายการยืมนั้น
3. รายการยืมอยู่ในสถานะ `Borrowed`

#### Post-conditions

1. ข้อมูลรูปภาพ สภาพสิ่งของ และ Timestamp การส่งคืนถูกผูกเข้ากับ Transaction ใน Database
2. สถานะของรายการยืมอัปเดตเป็น `Returned`
3. สถานะของสิ่งของเปลี่ยนกลับเป็น `Available`

#### Acceptance Criteria & Test Cases

- [ ] **Test Case 1:** User บันทึกหลักฐานการส่งคืนถูกต้อง ข้อมูลและรูปภาพถูกบันทึกลง Database สถานะการยืมเปลี่ยนเป็น `Returned` และสถานะสิ่งของเปลี่ยนกลับเป็น `Available`
- [ ] **Test Case 2:** User ส่งแบบฟอร์มบันทึกหลักฐานการส่งคืนโดยไม่แนบรูปภาพ หรือกรอกข้อมูลบังคับไม่ครบ ระบบต้องแจ้งเตือนข้อผิดพลาดและไม่บันทึกข้อมูลลง Database
- [ ] **Test Case 3:** ผู้ใช้ที่ไม่ได้เป็นคู่กรณี พยายามส่งข้อมูลบันทึกหลักฐานการส่งคืน ระบบต้องปฏิเสธการดำเนินการ

### US-08: เรียกดูประวัติและหลักฐานการยืม-คืนสิ่งของ

- **As a:** นักศึกษาและบุคลากรของมหาวิทยาลัยธรรมศาสตร์ที่มี TU Account
- **I want to:** เปิดดูประวัติการยืม-คืน พร้อมรูปภาพหลักฐานและรายละเอียดสภาพสิ่งของทั้งช่วงรับของและคืนของ
- **So that:** ตรวจสอบความถูกต้องของรายการยืมและใช้เป็นหลักฐานอ้างอิงได้อย่างโปร่งใส
- **Priority:** Low
- **Estimate:** 1 point

#### Pre-conditions

1. User อยู่ในสถานะเข้าสู่ระบบ
2. User เป็นคู่กรณีในรายการยืมนั้น
3. มีรายการยืมและประวัติการบันทึกหลักฐานอยู่ในระบบ

#### Post-conditions

1. ข้อมูลและรูปภาพหลักฐานถูกดึงมาแสดงผลบนหน้าจออย่างถูกต้อง ครบถ้วนตามสิทธิ์

#### Acceptance Criteria & Test Cases

- [ ] **Test Case 1:** ผู้ยืมหรือผู้ให้ยืมเปิดดูประวัติรายการยืม ระบบแสดงรูปภาพและรายละเอียดหลักฐานทั้งช่วงรับของและคืนของได้อย่างถูกต้อง
- [ ] **Test Case 2:** บุคคลภายนอกที่ไม่ใช่คู่สัญญาในรายการยืมนั้น พยายามเปิดดูหรือเข้าถึง URL/API ของหลักฐาน ระบบต้องไม่อนุญาตและปฏิเสธการเข้าถึง

### US-09: Login ด้วย TU Account

- **As a:** นักศึกษาและบุคลากรของมหาวิทยาลัยธรรมศาสตร์ที่มี TU Account
- **I want to:** Login เข้าใช้บริการตาม Role ของ User ด้วย Username & Password
- **So that:** User เข้าใช้บริการได้ด้วยบัญชีของมหาวิทยาลัย
- **Priority:** Low
- **Estimate:** 1 point

#### Pre-conditions

1. User ต้องมี TU Account ที่สามารถใช้งานได้ตามปกติ
2. User ต้องอยู่ในหน้า login ของบริการ
3. บริการ TU REST API ของมหาวิทยาลัยธรรมศาสตร์ต้องใช้งานได้

#### Post-conditions

1. User ต้องเข้าสู่ระบบได้สำเร็จด้วย Session ที่ระบบออกให้
2. สามารถใช้ Service ที่ผูกกับบัญชีของ User ได้

#### Acceptance Criteria & Test Cases

- [ ] **Test Case 1:** Login ด้วยข้อมูลถูกต้อง สามารถเข้าสู่ระบบได้สำเร็จตาม Role
- [ ] **Test Case 2:** Login ด้วยรหัสผ่านผิด ระบบแจ้งเตือนและไม่อนุญาตให้เข้าสู่ระบบ
- [ ] **Test Case 3:** Login ด้วยข้อมูลหลังการเปลี่ยนแปลงใดๆ ใน TU Account โดยที่สามารถเข้าสู่ระบบได้สำเร็จตาม Role
- [ ] **Test Case 4:** Login ด้วยข้อมูลก่อนการเปลี่ยนแปลง หลังจากการเปลี่ยนแปลงใดๆ ใน TU Account โดยที่ไม่สามารถเข้าสู่ระบบได้สำเร็จ
- [ ] **Test Case 5:** หลังจากที่สามารถเข้าสู่ระบบได้สำเร็จแล้ว ควรแสดงข้อมูลที่ผูกติดกับบัญชีอาทิ `username` หรือ `role` เป็นต้น ได้อย่างถูกต้องตามบัญชีนั้นๆ และสามารถใช้ได้เฉพาะบริการที่ถูกอนุญาตให้ใช้งานกับ role นั้นๆ
